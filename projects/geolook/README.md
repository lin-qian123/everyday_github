# geolook

## 定位

`geolook`（GeoLook）是一个本地自托管的生成式引擎优化（GEO）工作台：围绕具体网站完成抓取、诊断、提问采样、工单、内容/部署资产与前后期验收。这里的 GEO 指提升品牌在生成式搜索回答中的提及与引用，不是地理信息系统。

截至 2026-07-30，GitHub API 显示仓库创建于 2026-07-29，约 14 stars、8 forks，MIT 许可证；它是早期开发者信号，项目 README 中的方法和数据结论需要按来源与样本自行复核。

## 用法

项目提供 Python CLI 和只绑定 loopback 的本机看板。首次可先启动 UI、检查生成的品牌事实和问题库；只有在人工确认后，才配置模型 API 并运行自动采样或生成草稿。

```bash
git clone https://github.com/bingqiang2021/geolook.git
cd geolook
python scripts/geo.py ui
```

## 原理

它将品牌官网抓取、六维体检、竞争对手/问题库推导、跨引擎回答采样、行动工单与验收串为文件式项目流程。无 API key 时可导出人工采样表；有 key 时会调用模型做部分推导和初稿，但发布仍设计为人工确认。

## 价值

- 将“模型是否提及品牌”的模糊营销需求拆成可记录的提问、样本、差距、行动和复测。
- 本机优先、数据文件化的架构方便审查项目产物，避免一开始就依赖黑盒 SaaS。

## 风险边界

- 生成式回答受模型版本、检索、地域、提示词和时间影响；少量采样不能证明长期排名或因果收益。
- 任何“优化”不应滑向伪造来源、操纵性内容或误导性声明；事实库、引用和发布责任仍由人承担。
- `.env`、`work/` 与采样回答可能含 API key、客户和竞争信息；远程访问应走 SSH 隧道或额外认证。

## 补充建议

预注册问题集、记录每次模型/地区/日期与完整原始回答，并对照自然流量、转化和用户满意度；先在自有测试站点验证，避免把自动生成内容直接投入生产发布。
