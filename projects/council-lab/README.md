# council-lab

## 定位

`council-lab` 是本地优先、允许人中途介入的多模型审议工作台。它按顺序组织四个讨论席位，在用户确认或补充后由总结席给出最终答案，并保留可导出的过程记录。

截至 2026-07-28，GitHub API 显示其创建于 2026-07-27，约 9 stars、2 forks；属于早期开发者信号。

## 用法

可用项目提供的本地演示先验证交互；接入真实 provider 时，在设置中逐个配置账户与模型，设置调用次数、token、时间预算和资料范围。源码运行可使用项目的 `setup.sh` 与 `start.sh`。

## 原理

四个角色对同一公开上下文依序发言，后续角色读取前文并可响应用户插话；运行快照、资料、预算和 checkpoint 被持久化，最后由单独调用完成综合。项目明确不展示或保存模型隐藏思维链。

## 价值

- 将“多模型给四个平行答案”转为可回看、可质疑、可中断的决策过程。
- 调用/Token/时间上限与恢复机制有助于控制成本并留下失败证据。

## 风险边界

- 多席位一致不等于事实已经验证；项目自身不执行联网检索或代码沙箱。
- 所有真实调用仍会把问题和公开上下文发送给所选 provider，并可能产生费用。
- 开源桌面包未必带有平台签名；应核对 release 哈希、来源和权限。

## 补充建议

把高风险结论的原始资料、外部核验与最终决策人分开记录；先用 mock provider 建立预算、恢复和导出流程的回归样例，再接入真实密钥。
