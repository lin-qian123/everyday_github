# dreamvault

## 定位

`dreamvault` 提出长记忆 AI companion 的“幻觉隔离而非直接删除”治理模式，并给出参考实现：未锚定生成内容进入与主记忆、检索路径物理分离的 vault，由生成者本人在专用界面查看与认领。

截至 2026-07-29，GitHub API 显示其创建于 2026-07-28，约 8 stars、1 fork；代码为 Apache-2.0、文档为 CC BY 4.0。其叙事与治理主张需与可测系统效果区分开看。

## 用法

仓库提供规范、参考实现、最小示例和 sovereignty tests。应先以合成数据运行测试与审阅 import graph，确认 vault 数据不会被 agent 默认 `search()` 或普通检索链路重新注入上下文，再考虑适配自己的记忆系统。

```bash
git clone https://github.com/SilviaYue/dreamvault
cd dreamvault
# 按仓库当前开发依赖与测试说明运行其示例和 sovereignty tests
```

真实用户记忆、原文和身份信息不应为了试验而导入公开或共享环境。

## 原理

设计把未锚定内容视作需要隔离的高风险工件，而非自动回写的事实：vault 与主记忆分库，机器路径缺少自动检索接口；后处理以第三人称摘要分离虚构场景与可能的驱动；仅“梦的生成者”可认领或书写其叙事。项目以测试断言隔离墙存在。

## 价值

- 为长期记忆系统提供“防污染”和“保留/可查看”之间的具体架构折中。
- 把所有权、访问路径和误标成本写成实现约束，而非仅停留在提示词规则。

## 风险边界

- 这是面向 AI companion 的规范性治理方案，不证明幻觉检测、情感解释或人格归属在技术/伦理上已达成共识。
- “宁可漏过”会留下未隔离内容；过度隔离又可能隐藏真实记忆，阈值、申诉与人工治理都不可省略。
- 隔离库仍包含高度敏感内容；加密、访问控制、保留/删除、导出权与地区隐私法规需要独立设计。

## 补充建议

将事实记忆、模型推断和用户可叙述内容分级建模；为每一次隔离保留可审计理由和可逆流程，并以合成矛盾数据衡量误隔离、漏隔离及检索泄漏。
